# 방기준

**내 기준으로 고르는 자취방** — 여러 자취방의 비용, 면적, 통학시간과 장단점을 직접 기록하고 비교하는 브라우저 앱입니다. 점수로 최고의 집을 정하거나 추천하지 않고, 사용자가 저장한 조건별 충족 여부를 보여줍니다.

## 주요 기능

- 매물 등록·조회·수정·확인 후 삭제, 관심 표시
- 보증금·월 고정비·통학시간·면적·최소 준공연도 조건 저장, 빈 조건 제외, 경계값 포함 판정
- 최신/월 고정비/통학시간/면적 정렬, 관심/모든 조건 충족 필터
- 최대 3개 비교표, 수정·삭제 즉시 반영, 필터·정렬과 독립적인 비교 선택
- 준공연도를 포함한 가상 예시 6개: 고정 ID로 중복 방지, 기존 예시 자동 업데이트와 개인 매물 보존
- 한국어 반응형 화면, 필드별 오류, 안전한 외부 링크, 저장 실패와 손상 데이터 안내
- 준공연도 선택 입력, 현재 연도 기준 경과 연수·건물 연차 표시, 준공연도 양방향 정렬
- 카드·비교표의 ㎡/평 표시 전환과 매물 입력 중 평수 미리보기

## 준공연도와 평 표시 사용법

매물의 **수정** 또는 **매물 추가**에서 `준공연도`를 입력하세요. 모르면 비워 둘 수 있습니다. 네 자리 정수(1000년~현재 연도)만 허용하며, 미래·음수·소수 연도는 저장할 수 없습니다. 정확한 준공 월·일을 입력하는 방식은 아닙니다. 한국 시간(Asia/Seoul)의 현재 연도로 계산하여 `2020년 준공 · 6년 경과 (7년차)`처럼 표시합니다(2026년 기준). 준공한 해는 0년 경과·1년차이고 월·일은 반영하지 않습니다.

**내 조건 설정 → 최소 준공연도**에 원하는 기준 연도를 입력하고 **조건 저장**을 누르세요. 예를 들어 `2020`이면 2020년을 포함해 그 이후에 준공된 매물이 충족합니다. 빈 값은 비교에서 제외합니다. 연도 조건은 다른 네 조건과 함께 충족 개수와 **모든 조건 충족** 필터에 반영됩니다. 준공연도가 없는 매물은 **확인 불가 · 준공연도 미입력**으로 표시하고 충족 개수에 포함하지 않으며, 모든 조건 충족 필터에서도 제외합니다. 필터를 켜지 않으면 충족 여부와 관계없이 목록에 남습니다.

이전 목록의 연대별 분류 메뉴는 최소 준공연도 조건으로 대체했습니다. **매물 정렬**의 `준공연도 최신순`, `준공연도 오래된 순`은 유지하며, 미입력 매물은 어느 방향에서나 마지막입니다. 준공연도 조건은 새로고침 후에도 유지되고 조건·필터 변경으로 비교 선택이 해제되지 않습니다.

**면적 표시 → 평**을 누르면 카드와 비교표를 평수로 보여줍니다. `1㎡ = 0.3025평`으로 환산하고 소수 둘째 자리까지 반올림하며 `약`을 붙입니다. 예를 들어 20㎡는 약 6.05평입니다. 입력·저장·조건 판정과 면적 정렬은 원래 ㎡ 값을 사용하므로 단위를 바꿔도 계산 결과와 데이터가 변하지 않습니다. 입력 폼에서도 입력한 면적의 평수를 미리 볼 수 있습니다. 표시 단위·필터·정렬은 새로고침 시 초기화됩니다.

기존 `bang-gijun:v1` 저장 데이터는 계속 읽을 수 있습니다. 개인 매물의 `builtYear`가 없으면 미입력으로 취급합니다. 새 입력이나 수정은 `builtYear: 숫자 또는 null`로 저장합니다. 기존 가상 예시의 비어 있는 준공연도는 아래의 예시 업데이트에 따라 채웁니다.

기존 네 조건만 있는 데이터는 읽을 때 메모리에서 `minBuiltYear: null`만 보완합니다. 저장된 다른 조건과 매물은 보존하며 원본 저장소는 다음 사용자 저장 또는 예시 업데이트의 저장에 성공할 때 갱신합니다. 최소 준공연도도 1000년~현재 연도의 네 자리 정수만 허용합니다.

## 가상 예시 6개

아래 정보와 준공연도는 모두 비교 연습용으로 만든 가상 값입니다. 실제 매물·실제 건물 정보가 아니며 실제 주소나 매물 링크를 제공하지 않습니다.

| 이름 | 보증금(만 원) | 월세(만 원) | 관리비(만 원) | 면적(㎡) | 통학(분) | 준공연도 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 응암 A | 2,000 | 55 | 10 | 20 | 38 | 2018 |
| 염창 B | 1,000 | 65 | 10 | 19 | 40 | 2012 |
| 연희 C | 3,000 | 63 | 7 | 22 | 25 | 2020 |
| 상수 D | 1,500 | 48 | 7 | 17 | 45 | 2008 |
| 신촌 E | 3,000 | 78 | 8 | 24 | 12 | 2022 |
| 망원 F | 2,500 | 68 | 9 | 28 | 32 | 2015 |

첫 방문은 계속 빈 목록입니다. **예시 매물 불러오기**를 누르면 6개를 추가합니다. 기존 예시를 사용하던 브라우저는 새로고침 시 한 번 자동으로 새 예시를 추가하고 비어 있는 예시 준공연도를 채웁니다. 직접 등록한 매물, 예시에 입력한 준공연도, 수정한 비용·메모·관심 표시와 조건은 유지됩니다. 따라서 개인 매물이 있으면 전체 목록은 6개보다 많을 수 있습니다.

자동 업데이트를 성공적으로 저장한 뒤에만 화면을 변경하고 `examplesVersion: 2`를 기록합니다. 이후 사용자가 예시를 삭제하거나 연도를 비워도 새로고침으로 다시 복원하지 않습니다. 명시적으로 **예시 매물 불러오기**를 누르면 누락 예시와 빈 예시 연도를 다시 채웁니다. 자동 업데이트 저장 실패 시 원본과 화면을 유지하고 안내하며, 같은 버튼으로 재시도할 수 있습니다.

월 고정비는 **월세 + 관리비**이며 보증금을 포함하지 않습니다. 금액 단위는 만 원, 면적은 ㎡, 통학시간은 분입니다. 금액과 면적은 소수를 허용하고 통학시간은 0 이상의 정수로 입력합니다. 매물 면적과 최소 면적 조건은 0보다 커야 합니다. 표현 가능한 유한한 숫자만 받습니다. 금액 계산에서는 십진수 문자열을 이용해 `0.1 + 0.2` 같은 부동소수점 경계 오류를 피합니다.

로그인, 외부 DB, 유료 API, 지도, 자동 매물 수집, 실시간 경로 검색, AI 추천은 사용하지 않습니다. 외부 폰트 요청 없이 시스템 글꼴을 사용합니다.

## 설치 및 실행

Node.js 22.12 이상 권장. 이 작업에서는 Windows의 Node.js 26.7.0 / npm 11.19.0으로 실행했습니다. 프로젝트 폴더에서:

```sh
npm ci
npm run dev
```

표시된 로컬 주소(기본 `http://127.0.0.1:5173`)를 브라우저로 엽니다. 개발 서버 종료는 `Ctrl+C`입니다. Windows PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 사용하세요.

```sh
npm test          # 계산·조건·입력·저장 로직 자동 테스트
npm run test:e2e  # Chrome으로 데스크톱·모바일 화면 자동 테스트
npm run build    # TypeScript 검사 + 프로덕션 dist 생성
npm run preview  # 빌드 결과 로컬 확인
```

브라우저 테스트는 PC에 설치된 Google Chrome을 사용합니다. Chrome이 없다면 먼저 설치하거나 `playwright.config.ts`의 `channel`과 브라우저 설치 구성을 해당 환경에 맞춰 변경하세요. 테스트는 별도 브라우저 컨텍스트에서 실행하며 평소 사용하는 Chrome 프로필의 데이터를 읽거나 수정하지 않습니다. 테스트 종료 시 테스트용 서버도 종료합니다.

## 데이터 흐름

1. 앱 시작 시 `bang-gijun:v1` 키의 JSON을 읽고 버전, 필드 타입, 범위, 고유 ID, 링크를 검증합니다. 처음 방문하면 빈 목록을 표시합니다.
2. 입력 중에는 숫자도 문자열로 보관해 빈 값과 `0`을 구분합니다. 저장을 누르면 필드별 검증 후 숫자로 변환합니다.
3. 신규 매물에는 `crypto.randomUUID()`와 등록 시각을 부여합니다. 수정 시 기존 ID·등록 시각·관심 표시를 유지합니다.
4. 다음 데이터를 `localStorage.setItem`으로 먼저 저장합니다. 성공한 경우에만 React 상태를 갱신하고 성공 문구를 표시합니다. 실패하면 기존 목록과 입력 폼을 유지하고 오류를 안내합니다.
5. 목록과 비교표는 같은 최신 매물 배열을 참조합니다. 비교 선택은 ID 배열이며 정렬·필터와 독립적입니다. 삭제 저장에 성공하면 선택 ID에서도 제거합니다.
6. 조건, 관심 표시, 매물은 새로고침 후 복원됩니다. 비교 선택·정렬·필터·저장 전 폼은 임시 화면 상태로 새로고침 시 초기화됩니다.

저장 형식은 `{ version: 1, rooms: [...], conditions: {...}, examplesVersion?: 2 }`입니다. 빈 조건은 `null`, 실제 0 조건은 숫자 `0`으로 저장합니다. 예시 ID는 `example-1`~`example-6`이며 다시 불러올 때 기존 수정 값은 유지하고 빈 예시 준공연도만 채웁니다. 삭제한 예시는 불러오기 버튼으로 다시 추가할 수 있습니다.

## localStorage 선택 이유와 한계

작은 수업 과제에서 서버·계정·비용 없이 같은 브라우저에 데이터를 유지할 수 있어 선택했습니다. 저장 예외를 처리하며, 손상된 데이터는 자동 삭제하거나 덮어쓰지 않습니다. 읽기 오류 후 새 저장을 시도하면 기존 데이터를 대체할지 브라우저 확인창으로 묻습니다. 복구를 원하면 대체하기 전에 개발자 도구에서 원본 키를 별도로 보관하세요.

데이터는 이 브라우저에 저장되며 다른 기기와 공유되지 않습니다. 브라우저 데이터 삭제, 프로필 변경, 시크릿 모드 종료 등에 따라 사라질 수 있습니다. 저장 용량 제한이 있고 암호화 저장·백업·내보내기는 제공하지 않습니다. 배포 도메인, 포트, 프로토콜이 바뀌면 별도 저장소이므로 로컬 개발 데이터는 배포 사이트로 자동 이동하지 않습니다. 여러 탭을 동시에 편집하면 마지막 저장이 우선하므로 한 탭에서 사용하는 것을 권장합니다. 손상 데이터의 일부만 자동 복원하는 기능은 없습니다.

## GitHub 업로드

GitHub 로그인과 본인 계정의 저장소 생성은 사용자가 진행합니다. 비어 있는 새 저장소를 만들고 아래의 `YOUR_ACCOUNT`를 실제 계정으로 바꾸세요. 아래 명령은 저장소 업로드 절차이며 개발 중 원격 업로드를 실행한 것은 아닙니다.

```sh
git init -b main
git add .
git commit -m "Build Banggijun room comparison app"
git remote add origin https://github.com/YOUR_ACCOUNT/bang-gijun.git
git push -u origin main
```

`node_modules`, `dist`, 캐시, 테스트 임시 결과는 `.gitignore`에 포함되어 있습니다. `package-lock.json`은 재현 가능한 설치를 위해 함께 커밋합니다. Git 사용자 이름·이메일과 GitHub 인증이 설정되어 있어야 합니다. [GitHub 공식 안내](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)를 참고하세요.

## Vercel 배포

1. Vercel에 로그인하고 **Add New → Project**에서 GitHub 저장소를 가져옵니다. 처음 연결할 때 저장소 접근 권한을 부여합니다.
2. 프로젝트 루트는 이 폴더, 프레임워크는 **Vite**, 빌드 명령은 `npm run build`, 출력 폴더는 `dist`로 설정합니다. 환경변수는 필요하지 않습니다.
3. Deploy를 누르고 빌드 완료 후 제공되는 HTTPS 주소를 엽니다. 이후 연결된 브랜치의 커밋은 Vercel 설정에 따라 재배포됩니다.
4. 배포 URL에서 등록·새로고침·비교를 다시 확인합니다. 제출할 때 저장소 URL, 배포 URL, DEVLOG와 실제 화면을 함께 첨부하면 됩니다.

단일 페이지이며 별도 경로 라우팅이 없어 모든 경로를 재작성하는 설정은 필요하지 않습니다. 설정 근거는 [Vercel Vite 공식 문서](https://vercel.com/docs/frameworks/frontend/vite)입니다. 실제 계정 연결 및 공개 배포는 아직 실행하지 않았습니다.

## 직접 확인할 체크리스트

자동 브라우저 검증은 에뮬레이션이므로 다음은 사용 환경에서 추가 점검하세요.

- [ ] 배포 URL에서 매물·관심 표시·조건을 저장하고 실제 브라우저를 완전히 종료한 후 다시 열어 복원 확인
- [ ] 실제 Android/iPhone에서 숫자 키보드, 수정·삭제, 긴 메모, 비교표 터치 가로 스크롤 확인
- [ ] Safari/Firefox에서 주요 기능과 저장소 접근 제한 안내 확인
- [ ] 키보드 Tab/Shift+Tab으로 입력·저장·비교 조작, 스크린리더로 라벨과 오류 안내 확인
- [ ] 본인의 실제 매물 링크가 새 탭에서 정상 열리는지 확인
